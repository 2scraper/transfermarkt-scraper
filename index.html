Four modes today

    
Four, not twenty. This is a v0.1 release, scoped deliberately
      rather than promising coverage that was not built and checked yet — each row below
      is a real measurement, not a guess.

Two kinds of row, not one padded schema

    
A market value and a transfer fee are not the same kind of
      fact, so this scraper does not force them into one row shape with half its columns
      permanently empty.

    

      

        
Player rows

        
market-values, club-squad, player —
          position, club, nationality, market value, contract dates.

      

      

        
Transfer rows

        
transfers — both clubs, both leagues, the fee and its type:
          disclosed, loan, free, or undisclosed.

      

      

        
Shared prefix

        
Both open on the same id / title / price / currency / timestamp columns, so
          tooling written against one reads the other's shared fields unchanged.

      

    

  


  


  

    
Built from real pages, bugs and all

    
Two real parsing bugs were found and fixed while building
      this — documented rather than glossed over, because they're exactly the kind of
      thing that costs someone else an afternoon otherwise.


    

      
A doubled club name

      
A transfer's from_club came back
        "Without ClubWithout Club" for a free-agent placeholder. The site's
        own markup really does carry a doubled title attribute there,
        compounded by a second link in the same cell that wraps only an image. Fixed by
        reading the text-bearing anchor specifically.

    

    

      
Missing contract dates

      
joined_date and contract_until came back
        null on every player profile, despite being visible on the page. The
        header uses the same CSS class on two different tag types for these two fields
        versus the rest — a markup inconsistency on the site's own part. Fixed by
        matching both.

    

    
Both are now pinned cases in the
      offline test suite, checked against the exact capture that found them.

  


  


  

    
Three engines, one contract

    
Same modes, same flags, same output shape. Use whichever your
      stack already runs.

    

      

        recommended
        
Playwright

        
The only engine with --concurrency, safe on the one mode
          (transfers) measured to have genuinely independent pagination.

        
pip install playwright
playwright install chromium
python3 playwright_scraper.py --mode transfers --pages 5 --concurrency 4

      

      

        
Selenium

        
For teams already on WebDriver. Cannot authenticate a remote CDP endpoint or a
          proxy — documented, not silently broken.

        
pip install selenium
python3 selenium_scraper.py --mode market-values --pages 2

      

      

        
Puppeteer (pyppeteer)

        
Puppeteer's own API, in Python — not a Node.js process.

        
pip install pyppeteer
python3 puppeteer_scraper.py --mode player --player-id 418560

      

    

  


  


  

    
When a scrape needs more than a browser

    

      

        
Proxies, if you need them

        
Whether transfermarkt.com treats a datacentre address any differently from a
          residential one is genuinely unmeasured for this release — stated plainly
          rather than assuming the usual story. --proxy-file takes a pool the
          moment you need one.

        
Proxies at 2prx.com →

      

      

        
A challenge page instead of data

        
Cloudflare, DataDome, PerimeterX, reCAPTCHA and hCaptcha are all detected.
          Pass --twocaptcha-key and the scraper solves and continues on the
          same page.

        
Solver at 2captcha.com →

      

      

        
A fingerprint that doesn't add up

        
--fingerprint pulls a real device fingerprint — user agent,
          screen, locale, timezone, all consistent with each other — instead of a
          headless default that isn't.

        
Fingerprint data →

      

      

        
A managed, already-fingerprinted browser

        
Point --cdp-endpoint at the Scraping Browser API and the same
          script runs against a hosted Chrome profile with its own persistent cookies and
          exit country.

Quick start

    

      

        
1

        

          Install
          
Get the code and one engine.

          
git clone https://github.com/2scraper/transfermarkt-scraper
cd transfermarkt-scraper
pip install -r requirements.txt -r requirements-playwright.txt
playwright install chromium

        

      

      

        
2

        

          Run the offline suite
          
No network, no browser, ~1 second.

          
python3 smoke_test.py

        

      

      

        
3

        

          Scrape something real
          

          
python3 playwright_scraper.py --mode club-squad --club-id 281 --season 2025

        

      

      

        
4

        

          Add proxies and solving, if you need them
          

          
cp .env.example .env   # fill in TWOCAPTCHA_KEY / TRANSFERMARKT_PROXY
python3 playwright_scraper.py --mode transfers --pages 10 --concurrency 4

        

      

    

  


  


  

    
Questions

    

      
Where do the ids come from?

      
Transfermarkt's own URLs. .../profil/spieler/418560 is player
        418560; .../verein/281 is club 281 (Manchester City). Both are
        visible in any club or player URL on the site.


      
Will it break when the site changes?

      
Eventually, yes — any scraper does. Selectors live in one file
        (product_parser.py) shared by all three engines, so a layout change
        is usually a few lines in one place. --dump-html writes the exact
        page a run saw, so a report can include it.


      
Do I need the paid add-ons?

      
No. The scraper is complete and MIT-licensed on its own. Whether you need a
        proxy at all is, honestly, something this release cannot tell you yet — try
        without one first and see.


      
JSON or CSV?

      
Both, from the same run. List fields (a player's dual nationality) join with
        " | " in CSV so a cell stays readable in a spreadsheet, and stay a
        real list in JSON.


      
What's not here yet?

      
League tables, fixtures, match reports, coach and referee profiles, and
        Transfermarkt's other locale sites (.de, .es, ...) — all out of scope for this
        release, not silently broken. See the README's roadmap.
